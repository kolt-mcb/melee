# Console parity: character x stage

How far each mirror match stays **bit-identical to Dolphin**, in frames,
keyed by CKind (the CSS ordering the sweep uses), not FighterKind.
from `tests/pc/lockstep_baseline.json`.

Generated by `tools/pc_parity_doc.py`. Do not hand-edit.

Baseline recorded 2026-09-19.

> **Check the date before quoting these numbers.** The lockstep harness
> has been wrong about this grid before: it sampled the console at the
> GPU's frame boundary rather than after the simulation, reseeded the
> second fighter at the wrong moment, and freed JIT code it was
> executing. All three made cells look like they diverged when they had
> not. A baseline taken before those fixes reads pessimistically, and
> re-running the sweep is the only way to know which it is.

Read the number as frames, not a score. The simulation is exact until it
is not; after the first differing frame the two runs are different
matches, so a cell that parts at 300 is not "half right".

Left out entirely: **SEAK** -- no CSS icon, so the sweep cannot
select them and never ran those cells. Their stored 0s are absence of
measurement, not divergence on frame 0.

    ok    never parted inside the measured window
    <n>   the frame it first differs on
    .     not measured

## Summary

**This sweep ran 600 frames per cell**, so that number is a ceiling on the
measurement, not on the port. A cell showing `ok` never parted inside the
window; it is not known to be exact beyond it. Bars above 600 are not
reported -- no cell could have cleared them.

| bar | cells | share |
| --- | ---: | ---: |
| clean for the whole 600-frame window | 44 of 519 | 8% |
| identical through 60 frames | 241 of 519 | 46% |

The plan's definition of done is every cell clean at 7200 frames, which
needs the sweep's budget raised before it can even be asked.
