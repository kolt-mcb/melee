# Publishing checklist

Working notes for turning this branch into a public repository. The rule the
whole list serves: **the repository ships code, the user brings the game.**

## Done on this branch

- [x] **Reference frames removed from tracking.** `tests/pc/refs/` was 138
      Dolphin captures of the retail game — including stills of the intro
      movie, i.e. copied video. Now gitignored; regenerate with
      `tools/pc_suite.py capture`.
- [x] **GX traces removed.** `gx_trace/` was 600 files / 55 MB of renderer
      traces derived from the game's display lists.
- [x] **Debug screenshots removed.** Ten loose PNGs at the repo root.
- [x] **Launcher icon replaced.** The old one was a crop of the game's VS
      banner art. The new one is drawn by `tools/launcher/make_icon.py`,
      committed next to it so the provenance is checkable.
- [x] **Automated enforcement.** `tools/pc/check_no_game_data.py` rejects disc
      content, disc images, and images of the game; wired into
      `.pre-commit-config.yaml` and `.github/workflows/no-game-data.yml`.
- [x] **Extraction tool.** `tools/pc/extract_game.py` reads the user's own
      disc image, writes `orig/GALE01/`, and verifies the executable's SHA-1
      against the 1.02 target. Verified against a real disc: 1209 files, DOL
      SHA-1 matches.
- [x] **The dead `-i` flag fails loudly** instead of silently half-booting.
- [x] **`fs_init` fails fast when there is no game data.** Every miss further
      down was only a warning, so a wrong directory opened a window full of
      nothing instead of saying what was wrong. It now probes for `PlCo.dat`,
      prints the extraction command, and exits; a missing `boot.dol` warns.
- [x] **Personal absolute paths removed** from `tools/dolphin_ref.sh` (now
      `MELEE_ISO` / `MELEE_DOLPHIN`), `tools/agent/sweep_incomplete.py`, and
      the desktop entry (now generated by `install-desktop.sh`).
- [x] **`port-setup.sh` corrected.** It told users the GameCube build had to
      succeed first and that the PC port linked against its objects. Neither
      is true: `configure_pc.py` compiles the sources directly.
- [x] **The revision is verified at launch.** The port SHA-1s `boot.dol` and
      refuses to start on anything but 1.02, because a wrong revision does not
      degrade -- tables are read from fixed addresses, so it would silently
      read the wrong bytes. This is the pattern Zelda64Recomp uses and the
      strongest posture found in the survey.
- [x] **LEGAL.md, LICENSE, README.md, docs/pc/setup.md, docs/pc/precedent.md**
      written.

## Before pushing anything public

- [ ] **Rewrite history.** Removing files from the tip does not remove them
      from the 351 commits behind it. The port branch has **never been
      pushed** (the `fork` remote has no `pc-port`), so a local rewrite is
      completely effective; nothing has been exposed yet.

      This procedure was trial-run end to end and the numbers below are
      measured, not estimated.

      ```sh
      python3 -m venv /tmp/fr && /tmp/fr/bin/pip install git-filter-repo
      git clone --no-local --single-branch --branch pc-dist \
          /home/grunt/melee /tmp/melee-publish
      cd /tmp/melee-publish
      /tmp/fr/bin/git-filter-repo --force \
          --path tests/pc/refs --path gx_trace --path .pi \
          --path-glob 'screenshot*' --path-glob 'shot*.png' \
          --path-glob 'title_fix*.png' --path tev_test.png \
          --path gdb.txt --path tools/launcher/melee-pc.png \
          --invert-paths
      ```

      **Then regenerate the launcher icon**, which that last `--path` removes
      along with the old game-art one it is meant to purge:

      ```sh
      python3 tools/launcher/make_icon.py
      git add tools/launcher/melee-pc.png
      git commit -m "Regenerate the launcher icon after history rewrite"
      ```

      It comes back byte-identical (md5 `c5c32f5d…`), which is the point of
      generating it from a script.

      Verify nothing survived — expect no output:

      ```sh
      git rev-list --objects --all | grep -iE '\.(png|jpg|jpeg|ppm)$' | \
          grep -vE '^\S+ (\.github/assets|docs/img|tools/(asm-differ|launcher))/'
      python3 tools/pc/check_no_game_data.py --all
      ```

      Measured result: 20.28 MiB of packed objects before, **6.72 MiB** after,
      all 362 commits preserved, and the only images left in the entire
      history are the four tooling screenshots and the generated icon. (The
      raw blobs total 137 MiB; git's delta compression is why the pack is so
      much smaller than that.)

      *Simpler alternative:* publish a single squashed commit of the port work
      on top of upstream. It discards 362 commits of history but cannot leak
      what it never contained.

- [ ] **Decide the repository's form.** Recommended: publish as a **GitHub
      fork of doldecomp/melee**. Upstream ships no LICENSE, so no terms have
      been granted for the decompiled code; forking a public repository is
      something GitHub's Terms of Service provide for, and the fork
      relationship makes the attribution obvious. A standalone repository
      redistributing the same unlicensed code has a weaker footing.

- [ ] **Tell the upstream maintainers.** A courtesy note in the doldecomp
      Discord before publishing. Upstream's own README says a portable build
      is out of scope for that project; make clear this fork does not speak
      for them, and take their objections seriously if they have any.

- [ ] **Read [precedent.md](precedent.md) before deciding anything else here.**
      It records what the comparable projects actually do and what has drawn
      enforcement — including the one finding that should shape expectations:
      across all 88 Nintendo notices in GitHub's DMCA archive, none touches a
      decompilation, a port, Melee, or Slippi. The notices target disc images,
      circumvention keys, and bundled proprietary SDKs. Which makes the
      inherited SDK reconstruction under `extern/dolphin/` the highest-risk
      thing here — the Portal 64 analogue — not the game code.

- [ ] **Avoid netplay branding** if online play is ever added. Nintendo's
      Melee-specific actions (the Big House 2020, Smash World Tour 2022, the
      2023 tournament guidelines) have all been aimed at events and services
      rather than repositories.

- [ ] **Name it carefully.** Avoid a repository name, description or topic
      list that reads as the game's official name. "melee-pc" or
      "melee-decomp-port" describes what it is; "Super Smash Bros. Melee for
      PC" reads like a distribution of the game. Never attach box art, logos,
      or character renders.

- [ ] **Do not publish binaries.** GitHub's Terms of Service give users the
      right to fork a public repository regardless of its license, but only
      through GitHub. That covers the fork existing; it does not cover
      distributing binaries built from unlicensed upstream code. Source only.

- [ ] **Check the git identity** on the commits you publish (`git log
      --format='%an %ae' | sort -u`) — the whole history becomes public.

- [ ] **Re-run the audit on the rewritten clone**, not just here:
      `python3 tools/pc/check_no_game_data.py --all`.
